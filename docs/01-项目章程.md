# GameDailyAutomation 项目章程

版本：V1.0｜状态：需求基线｜平台：Windows 10/11｜形态：个人本地工具

## 1. 背景与目标
每天分别启动 BetterGI 和 March7th 完成原神与崩坏：星穹铁道每日任务，操作重复。本项目用轻量调度器串联现有工具，不重写游戏自动化逻辑。

目标：每天本机时间 17:00 后检查执行条件，先运行 BetterGI，再运行 March7th；记录结果；每个游戏失败最多自动重试一次；锁屏时等待解锁。

## 2. 成功标准
- 每天每个游戏最多一个成功终态，不重复执行已成功任务。
- 两个工具严格串行。
- 每个游戏最多两次总尝试。
- 单个游戏最终失败后仍继续另一个游戏。
- 锁屏时不向桌面盲目发送输入。
- 重启后能根据持久化状态恢复，不重复执行已完成任务。
- 每次执行有日志、耗时、尝试次数和最终结果。
- 不保存账号密码、Cookie、Token 等认证秘密。

## 3. 范围内
定时触发、登录/解锁补执行、进程启动与监控、顺序编排、锁屏检测、每日去重、SQLite 状态持久化、一次重试、超时与异常处理、日志、历史、通知、安装/卸载计划任务脚本。

## 4. 范围外
不开发/修改 BetterGI 或 March7th；不实现游戏内识图、战斗、寻路或键鼠逻辑；不绕过反作弊、验证码、登录验证；不做自动 Windows 解锁；不做云端、多用户、手机 App 或复杂 GUI；不保证关机期间执行；不保证锁屏状态下第三方桌面自动化可运行。

## 5. 已确认决策
| 项目 | 决策 |
|---|---|
| 触发 | 每天本机时间 17:00 后 |
| 顺序 | BetterGI → March7th |
| 执行方式 | 串行，不并行 |
| 锁屏 | 等待用户解锁，不自动解锁 |
| 失败 | 每个游戏自动重试一次 |
| 最大尝试 | 每游戏 2 次（含首次） |
| 失败隔离 | 一个游戏最终失败不阻断另一个 |
| 平台 | Windows 本地电脑 |

## 6. 运行原则
安全优先、状态优先、可恢复、不误报成功、有界重试、最小权限、配置外置、可观测。进程退出不能单独作为游戏任务成功依据；结果不明标记 UNKNOWN，不盲目重试。

## 7. 风险
第三方 CLI 升级：适配器隔离并在接入时重新验证；锁屏：等待解锁；进程结果不明：UNKNOWN/人工检查；任务重复：SQLite 唯一约束与单实例锁；唤醒不稳定：仅尽力配置 Task Scheduler，不作硬件层保证。

## 8. 交付物
源码、配置模板、计划任务安装/卸载脚本、日志与历史、README、单元/集成测试、项目规范文档。

## 9. 版本原则
V1.0 优先稳定、可恢复、可诊断；后续再考虑托盘 UI、更多游戏适配器和统计面板。
