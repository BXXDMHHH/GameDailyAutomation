# 需求规格说明书（SRS）

版本：1.0｜项目：GameDailyAutomation

## 1. 用户场景
用户希望每天 17:00 后自动执行原神和星铁每日任务。17:00 时锁屏则等解锁；睡眠/关机错过时间则在系统唤醒或用户登录后补检查；已成功任务不重复执行。

## 2. 术语
- 工作流：一天内两个游戏任务组成的执行序列。
- 尝试：某游戏一次启动和执行。
- UNKNOWN：无法确认工具是否完成每日任务。
- 可安全重试：已确认失败且重复启动不会造成不可接受副作用。

## 3. 功能需求
### FR-001 定时与补执行
每天本机时间 17:00 触发检查；错过触发时间后在登录/解锁时补检查。17:00 是检查触发时间，不保证锁屏或未登录时立刻开始。

### FR-002 顺序编排
固定 BetterGI → March7th；不得并行。第一个任务进入终态后再处理第二个。第一个游戏最终失败不阻断第二个。

### FR-003 BetterGI
从配置读取 exe 路径、工作目录、参数和超时。调用用户预先配置的每日任务配置组。具体 CLI 参数及配置组名必须按本机版本帮助和实测确认，不得猜测。

### FR-004 March7th
优先调用官方发布版 m7a.exe。接入前检查本机 --help 和任务列表，任务名与参数以当前版本为准，不把旧版源码运行命令写死。

### FR-005 锁屏/会话
锁屏时不启动需要桌面交互的任务；保留待执行状态；解锁后重新检查。不得自动输入 Windows 密码或绕过锁屏。执行中锁屏则暂停后续编排，将当前任务记为 INTERRUPTED/UNKNOWN，解锁后先检查进程和日志再决定是否恢复。

### FR-006 睡眠/登录
Task Scheduler 尽可能配置 StartWhenAvailable、登录触发、解锁触发及可选 WakeToRun。是否能唤醒由系统电源策略和硬件决定，不作绝对保证。

### FR-007 去重与持久化
以本机业务日期识别每日任务。每个游戏成功后当天不再执行。每次启动前先持久化 RUNNING。发现遗留 RUNNING 时先检查进程和日志，不得直接重启。仅一个调度器实例可运行。

### FR-008 重试
每游戏最多 2 次总尝试。仅明确失败且可安全重试时重试；默认间隔 60 秒，可配置。验证码、认证失败、更新/确认弹窗、结果未知等不自动重试，转 NEEDS_ATTENTION/UNKNOWN。重试前再次检查锁屏、进程和完成状态。

### FR-009 超时
每个游戏配置最大运行时间。超时先收集日志与状态；不能仅凭超时认定失败。默认 UNKNOWN，只有适配器确认可安全重试才重试。

### FR-010 日志/历史
每次工作流有 run_id。记录业务日期、游戏、尝试序号、开始/结束时间、PID、退出码、状态、错误摘要和日志路径。日志轮转；不记录凭据。历史库损坏时备份并报告。

### FR-011 通知
结束后提供本地摘要，区分全部成功、部分失败、需人工处理。通知失败不改变任务结果。

### FR-012 配置
JSON 配置包含时间、启用状态、程序路径、工作目录、参数、超时、重试间隔和日志级别。配置无效/路径不存在时明确报错。不得保存账号凭据。

### FR-013 计划任务
提供幂等安装/卸载脚本；以当前用户交互会话运行，不使用 SYSTEM 会话执行桌面自动化。

## 4. 非功能需求
- 稳定性：SQLite 事务；启动恢复遗留状态；原子化配置/状态写入。
- 可维护性：第三方差异封装在 adapters；编排器不拼接 CLI。
- 可观测性：每次状态变化写日志，包含时间、级别、模块、run_id。
- 安全性：默认不提权；subprocess 参数列表、shell=False；不存秘密。
- 性能：空闲资源占用低，不高频轮询。
- 可移植性：Windows 10/11，系统相关代码集中在 system。

## 5. 状态
工作流：PENDING、RUNNING、COMPLETED、PARTIAL_FAILED、NEEDS_ATTENTION、CANCELLED。
单游戏：NOT_STARTED、RUNNING、SUCCEEDED、FAILED、RETRY_WAIT、INTERRUPTED、UNKNOWN、NEEDS_ATTENTION、SKIPPED。

## 6. 验收标准
1. 17:00 未锁屏：先 BetterGI 后 March7th。
2. 17:00 锁屏：解锁后恢复检查，不自动解锁。
3. 当天已成功：再次触发不重复执行。
4. 明确失败且安全可重试：只重试一次。
5. 两次失败：不进行第三次尝试，继续下一个游戏。
6. 结果不明：UNKNOWN，不盲目重试。
7. 崩溃恢复：检查数据库、进程、日志后恢复。
8. 第二实例启动：被单实例锁阻止。
9. 路径无效：给出明确错误，不静默跳过。
10. 通知失败：不改变已保存的任务状态。
