# 阶段 5：每日任务编排与重试

## 行为约束

- `DailyOrchestrator` 只在本机业务时间达到配置的 `schedule.time` 后运行；默认 17:00。
- 会话未解锁时不启动桌面任务，保持待处理并等待后续登录/解锁触发。
- 固定顺序 BetterGI → March7th；调用为同步串行，不创建并行任务。
- 每个游戏最多两次总尝试。每次尝试先由 SQLite 持久化 RUNNING，再调用适配器。
- 只有适配器返回明确 FAILED，且调用方注入的安全重试判定明确为 True，才进行一次重试。默认安全判定为 False。
- TIMEOUT、UNKNOWN、适配器异常均映射为 UNKNOWN，不自动重试。
- 一个游戏失败/未知不会阻止另一个游戏执行；只有两款游戏均 SUCCESS 才完成每日任务。
- 已成功的游戏在再次触发时跳过。已有 UNKNOWN、INTERRUPTED 或 RUNNING 状态不自动重跑。

## UNKNOWN 人工确认

调用 `SQLiteStateStore.resolve_unknown(..., confirmed_status, evidence_note, safe_to_retry=False)` 记录人工核验结果。只接受 SUCCESS 或 FAILED，且必须提供非空证据说明。只有人工明确设置 `safe_to_retry=True`，且仍未达到两次上限，后续触发才允许一次重试；UNKNOWN 本身不会自动变成可重试状态。人工确认单个游戏 SUCCESS 不会直接把每日总任务置为 SUCCESS。

## 集成边界

本阶段只提供可注入的会话状态函数与编排 API。Windows Task Scheduler 安装、解锁触发注册、Windows 会话检测及真实 CLI 结果判定仍需后续阶段接入。当前 `main.py` 不会启动游戏。测试仅使用 FakeAdapter 和临时 SQLite，不调用真实游戏程序。
