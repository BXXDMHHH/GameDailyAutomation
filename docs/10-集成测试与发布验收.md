## 重试语义和生产限制

重试集成场景明确注入测试用的安全判定器，仅用于验证编排与持久化机制。生产入口目前默认不批准自动重试；只有在对应第三方工具具备经过验证的失败证据分类器和安全重试策略后，才能开启自动重试。进程退出码 0 不等于游戏任务成功，TIMEOUT 和 UNKNOWN 均不得自动重试。

BetterGI 与 March7th 的真实任务完成判定仍需要本机版本日志/结构化结果的可靠证据。未验证之前，适配器会返回 UNKNOWN，这是预期的 fail-safe 行为，不应为通过测试而放宽。

## CI 首轮问题与修复记录

- 首轮运行：Ubuntu 70 项通过；Windows Server 2025 为 69 项通过、1 项失败。失败来自测试夹具在模拟 POSIX 清理路径时未提供 Windows Python 不存在的 `signal.SIGKILL` 常量；生产 Windows 清理路径使用 `taskkill`，未触发该 POSIX 分支。
- 已修正测试夹具，显式模拟 `SIGKILL` 常量。
- 修复后第二轮 CI（70 项版本）：Windows Server 2025 70/70 通过（5.747 秒）；Ubuntu 70/70 通过；整个 GitHub Actions matrix 结论为 success。
- 后续增加真实子进程启动失败、真实 Python 子进程超时清理，以及主程序遇损坏数据库时禁止构造适配器三项测试；扩展后的 CI 结果待运行确认。
