## 工具结果分类器（基于已提供的版本证据）

### BetterGI 0.67.0

- 配置项 games.bettergi.result_log_file 必须指向日志文件；支持环境变量和 {date} 占位符，例如 D:\\soft\\bettlegi\\log\\better-genshin-impact{date}.log，其中 {date} 按本机日期展开为 YYYYMMDD。
- 每次启动前记录日志文件字节偏移，只分析本次进程期间追加的内容，避免把历史会话的完成标记误判为本次成功。
- 只有退出码为 0、追加日志包含“一条龙和配置组任务结束”、且没有 [ERR]、“任务中断”或“任务被取消”时才判定 SUCCESS。
- 明确中断/取消或非零退出码判定 FAILED；日志缺失、轮转、截断、无完成标记或存在 [ERR] 时返回 UNKNOWN。[WRN] 不单独否定成功。
- [ERR] 与完成标记同时出现时保守返回 UNKNOWN，因为目前没有证据证明所有 [ERR] 都是致命错误。

### March7th v2026.11.8

- 解析 --json 命令 stdout 的最后一个非空行，必须是结构化运行记录。
- 记录必须满足 schema=1、task=daily、非空 run_id、有效 PID 和时间范围、lock=acquired。
- SUCCESS 还要求记录 status=success、记录退出码和外层进程退出码均为 0、reason 与 error 均为 null。
- FAILED 要求记录明确 status=failed、非零记录退出码与外层进程退出码一致。无 JSON 记录时，仅将已知 CLI 退出码 1–5 识别为明确失败；其中 5 表示 UAC 取消。
- status=aborted、用户停止（退出码 6）、JSON 缺失/损坏、任务类型不符、锁未取得、时间字段无效或退出码不一致均为 UNKNOWN。
- daily 返回 SUCCESS 代表 CLI 将该次工作流报告为成功；不代表每个可选子任务都实际执行。例如活跃度已满时，工作流可能合法跳过后续任务。

以上分类器规则依据用户提供的 BetterGI 日志摘要和 March7th 原始 JSON 运行记录。当前自动化测试使用可重复的样例夹具；尚未在用户机器上通过项目 ProcessRunner 对两个真实工具进行新的单工具验收。BetterGI 的 {date} 日志路径也必须在本机配置后验证。分类器通过测试不等于真实工具实测完成。

## 重试语义和生产限制

生产入口仍默认不批准自动重试。分类为 FAILED 只是确认本次任务没有成功，不代表重试一定安全；自动重试策略仍需单独验证并显式启用。TIMEOUT 和 UNKNOWN 均不得自动重试。
