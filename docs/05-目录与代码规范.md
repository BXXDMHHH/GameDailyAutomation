## 2. 模块职责
- core：工作流编排、重试、恢复、状态机。
- domain：领域模型、枚举、适配器接口和跨层数据模型，不依赖 Windows API 或第三方工具。
- adapters：BetterGI/March7th CLI 与工具专属结果解析。
- infrastructure：进程、SQLite、Repository、日志、单实例锁。
- system：Windows 会话、电源、计划任务、通知。
- config：配置读取与校验。
- scripts：安装、卸载、诊断脚本。
- tests：单元测试、显式启用的真实工具集成测试。

## 3. 命名
模块/函数/变量使用 snake_case；类使用 PascalCase；常量使用 UPPER_SNAKE_CASE；测试文件使用 test_<module>.py。游戏 key 固定为 bettergi、march7th。

## 4. 代码规范
- 公开接口使用类型标注；函数单一职责。
- 使用 pathlib 和带时区 datetime。
- SQL 参数化；数据库事务明确。
- 不硬编码个人绝对路径。
- subprocess 使用参数列表和 shell=False。
- 不使用空 except，不静默吞异常。
- 状态转换集中管理。
- 先持久化 RUNNING，再启动外部进程。
- 日志不包含密码、Cookie、Token。
- 真实游戏程序不得由普通单元测试启动。

## 5. 配置模板
~~~json
{
  "schedule": {
    "time": "17:00",
    "timezone": "local",
    "run_on_logon": true,
    "run_on_unlock": true,
    "wake_to_run": true
  },
  "execution": {
    "wait_for_unlocked_session": true,
    "retry_max_attempts": 2,
    "retry_delay_seconds": 60
  },
  "storage": {
    "database_path": "%LOCALAPPDATA%/GameDailyAutomation/data.sqlite3",
    "log_directory": "%LOCALAPPDATA%/GameDailyAutomation/logs"
  },
  "games": {
    "bettergi": {
      "enabled": true,
      "executable": "",
      "working_directory": "",
      "arguments": [],
      "version_arguments": [],
      "timeout_seconds": 7200
    },
    "march7th": {
      "enabled": true,
      "executable": "",
      "working_directory": "",
      "arguments": [],
      "version_arguments": [],
      "timeout_seconds": 7200
    }
  }
}
~~~

`arguments` 是日常任务的 argv 参数数组，`version_arguments` 是可选的版本探测 argv 数组。二者均默认为空；只能在目标机器查阅当前版本帮助并完成单独验证后填写。不要假设通用的 `--version` 开关存在。版本探测输出只作为诊断记录，必要时仍需人工核对版本号。

参数与超时仅为模板，须按本机实际版本验证；不得填写账号密码。

## 6. 测试规范
单元测试使用 FakeAdapter/FakeProcess，不启动真实游戏；覆盖状态转换、顺序、去重、重试上限、UNKNOWN、崩溃恢复、单实例。真实工具集成测试必须显式 opt-in。

## 7. Git 规范
提交信息示例：docs: add project baseline、feat: add task state persistence、test: cover retry and recovery。不要提交真实凭据、个人机器路径、运行日志、数据库或第三方二进制文件。
