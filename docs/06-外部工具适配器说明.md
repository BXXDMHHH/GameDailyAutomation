# 外部工具适配器说明（阶段 2）

本文区分公开文档已说明的能力、项目当前实现和必须在目标 Windows 机器完成的验证。任何本机验证结论都必须记录工具版本、完整命令参数、执行时间、退出码、日志/结构化结果证据；未验证内容不得升级为正式默认值。

## 1. 统一接口和边界

- `domain.adapter.GameAdapter` 定义 `game_key`、`check_available()`、`execute_daily()`、`identify_result()`。
- `BetterGIAdapter` 和 `March7thAdapter` 各自只绑定对应 `GameToolConfig`，独立初始化。
- 两个适配器共用 `infrastructure.ProcessRunner`，使用 argv 参数列表、`shell=False`，不拼接 shell 命令。
- 适配器不负责 BetterGI → March7th 的全局顺序。
- 配置中的 `arguments` 和 `version_arguments` 默认为空。只有用户在本机确认后才可填写；代码不推断 CLI 开关或任务 ID。
- 结果分类没有默认猜测规则。没有已验证的工具专属分类器时，即使进程退出码为 0，结果仍为 `UNKNOWN`。

## 2. 结果语义

| 结果 | 含义 |
|---|---|
| `NOT_CONFIGURED` | 可执行文件或任务参数尚未配置 |
| `START_FAILED` | OS 无法创建目标进程，例如路径错误或权限问题 |
| `SUCCESS` | 仅当经过验证的工具专属结果分类器确认任务成功 |
| `FAILED` | 仅当经过验证的工具专属结果分类器确认任务明确失败 |
| `UNKNOWN` | 超时、证据不足、状态不一致或尚无可靠分类规则 |

`ProcessRunner` 当前以 `subprocess.run` 同步等待并捕获输出。超时结果标记为 UNKNOWN；子进程树终止/接管、锁屏中断恢复和长时间持续监控属于后续基础设施阶段，当前不可据此宣称已解决。

## 3. BetterGI：公开资料与本机待验证项

官方命令行文档列出以下形式（仅为公开文档记录，不是本项目默认参数）：

- `BetterGI.exe start`
- `BetterGI.exe startOneDragon`
- `BetterGI.exe startOneDragon <配置名称>`（文档注明需要 0.45.3+）
- `BetterGI.exe --startGroups <配置组名称>`

官方文档提示 Windows 应使用命令提示符而非 Terminal/PowerShell，并且 `--startGroups` 后的名称来自 BetterGI 全自动调度器配置组。不同入口语义不同，不能互相替换。官方资料：[命令行启动](https://www.bettergi.com/feats/command/introduce.html)。

**本机必须确认：**
1. 实际 `BetterGI.exe` 路径和文件版本。
2. 用户希望运行的是“一条龙”配置还是“全自动调度器”配置组。
3. 对应配置名称及参数是否与本机版本匹配。
4. 按官方建议在 CMD 中单独试运行；再单独验证本项目 Python subprocess 的启动行为。
5. 采集一份正常完成和一份明确失败的日志/任务记录，确定可靠的结果标志；不能只看退出码。

BetterGI 官方 FAQ 说明运行需要 .NET 8 Desktop Runtime；若出现相关启动错误，需检查目标机器运行时：[BetterGI FAQ](https://www.bettergi.com/faq.html)。

## 4. March7th：公开资料与本机待验证项

March7th 官方站当前介绍随程序发布的 `m7a.exe` CLI，公开示例包括状态查询、任务列表、运行任务和跟踪最近一次运行；运行任务默认可能触发 UAC，需要用户本人确认。官方页面：[March7thAssistant](https://m7a.top/)。

**重要：** 公开页面/Skill 的 CLI 能力随版本演进。必须在目标机器运行该版本自己的帮助与状态查询，不能把网络示例直接当作本项目默认参数。

**本机必须确认：**
1. 安装目录、`m7a.exe` 路径、版本和安装登记状态。
2. 本机 `--help`、状态查询、任务列表的实际输出。
3. 目标任务 ID：`daily`（每日实训）还是 `routine`（日常）必须由用户明确选择；不得擅自替用户决定。
4. 运行任务的 UAC 行为、是否要求用户确认，以及取消/拒绝时的真实退出行为。
5. 正常完成、明确失败、被停止、UAC 取消和异常退出的 JSON/日志证据。
6. 确认完成后操作不会触发关机、睡眠、注销等行为。

不要绕过 UAC、免责声明或其他用户确认。可用性检查与实际任务启动分开进行；初始化 March7th 失败不得阻止 BetterGI 适配器单独构造，反之亦然。

## 6. 阶段门槛

当前实现提供适配器接口、独立适配器、统一进程调用边界、路径检查和可选版本探测。它**不代表真实工具集成验收通过**。

只有在目标 Windows 机器完成两个工具的独立启动、真实任务完成、明确失败识别、异常/取消行为记录，并为两者配置经验证的结果分类器后，才允许进入阶段 3 编排。未完成验证前保持配置参数为空，不启用自动调度。
