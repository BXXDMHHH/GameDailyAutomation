# 技术选型说明

版本：1.0｜目标平台：Windows 10/11

## 1. 选型原则
优先标准库、单机部署、第三方工具独立运行、Windows 特性隔离、所有 CLI 参数以本机版本验证为准。

## 2. 技术栈
| 层 | 技术 | 用途 |
|---|---|---|
| 语言 | Python 3.12+ | 调度与编排 |
| 进程 | subprocess | 启动、监控外部工具 |
| 路径 | pathlib | Windows 路径 |
| 配置 | JSON | 用户配置 |
| 状态 | SQLite | 每日状态、尝试历史、事务 |
| 日志 | logging | 轮转日志 |
| 单实例 | Windows 文件锁/命名互斥量封装 | 防重复 |
| 会话检测 | ctypes + Windows WTS API | 登录/锁屏状态 |
| 定时 | Windows Task Scheduler | 17:00、登录、解锁触发 |
| 脚本 | PowerShell | 计划任务安装/卸载 |
| 测试 | unittest | 单元测试 |
| 打包（可选） | PyInstaller | 稳定后再打包 |

## 3. BetterGI 接入
官方 CLI 文档列出 BetterGI.exe start、startOneDragon、指定配置名称及 --startGroups 等入口（具体能力受版本影响）。建议用户在 GUI 预设每日任务配置组，适配器从配置读取 exe、工作目录、参数；接入时先核对官方文档和本机版本并单独试运行。注意官方文档对终端调用方式可能有要求，必须实测 subprocess 调用方式。不要猜配置组名。

## 4. March7th 接入
优先使用官方发布版 m7a.exe。首次接入检查本机 --help 和任务列表，确认真实任务标识及正常结束参数。不得假设不同版本 CLI 完全一致，不使用过时源码启动方式作为唯一接口。

## 5. 统一适配器契约
建议 GameAdapter 提供 validate_config()、preflight()、start(context)、poll(handle)、collect_result(handle)、is_safe_to_retry(result)、request_stop(handle)。适配器不决定两个游戏的全局顺序。

## 6. SQLite
选择 SQLite 而非单个 JSON 历史文件，因需事务、唯一约束、尝试历史和崩溃恢复。建议表：daily_runs、game_runs、attempts；可选 state_events。数据库存放在 %LOCALAPPDATA%/GameDailyAutomation/，不要放源码目录。

## 7. Windows 计划任务
配置每日 17:00、用户登录、工作站解锁触发；尽可能启用 StartWhenAvailable，WakeToRun 作为可选项。必须在当前用户交互会话运行，不使用 SYSTEM 执行 GUI 自动化。唤醒能力受硬件和电源策略影响。

## 8. 锁屏和重试
锁屏时不启动新的桌面自动化。运行中锁屏则中断编排并将当前任务标记 INTERRUPTED/UNKNOWN，解锁后核对进程/日志。每游戏最多两次总尝试；UNKNOWN、认证失败、验证码或人工弹窗不自动重试。

## 9. 不采用
- BAT 串联：状态恢复、去重、诊断能力不足。
- 并行运行：可能争用桌面、游戏窗口和输入设备。
- 合并第三方源码：升级冲突和维护成本高。
- 云端调度：实际操作依赖本机桌面。
- 高频轮询：浪费资源并可能干扰睡眠。
